# Architecture

One process in the demo: FastAPI serves the API under `/api` and the built React app (`web/dist`) under `/`.

```text
 voice ──► gpt-live-transcribe ──► transcript
 (browser, WebRTC, ephemeral token from POST /api/transcribe/session)
                                       │
                                       ▼
                 POST /api/symptoms/extract
                 local HPO synonym search → candidates
                 gpt-6-luna (JSON Schema, enum of candidates) → [{hpo_id, present, quote}]
                                       │
                                       ▼
                 POST /api/diagnose            POST /api/next-question
                 likelihood ratios over        max information gain
                 12,867 diseases (local)       between the top two
                                       │
                                       ▼
 GET /api/graph/overview ──► constellation (precomputed x/y, dims and prunes with the ranking)
                                       │
                                       ▼
                 GET /api/node/{id} · GET /api/edge/{id} · POST /api/explain
                 curated deep layer, every edge with source and evidence level;
                 gpt-6.1-sol explains citing only [edge_id] that exist
                                       │
                                       ▼
                 POST /api/action-plan
                 groups, registries, studies, trials, this week's step, 10× timeline
```

## Backend (`app/`)

| Path | Role |
|---|---|
| `main.py` | Auto-discovers every `routers/<feature>.py`; mounts `web/dist` last so `/api/*` always wins |
| `schemas/` | Shared Pydantic contracts (`extra="forbid"`); one sample response per endpoint in `fixtures/api/` |
| `services/scoring.py` | Likelihood-ratio scoring, ranking, ranges, drivers and next question |
| `services/symptoms.py` | Candidate search, structured extraction, ephemeral transcription token |
| `services/explain.py` | Node, edge and the family explanation over the deep layer |
| `fixtures/graph/` | `overview.json` (layout) and `annotations.json`, generated by `data/build.py` |
| `fixtures/deep/` | Curated deep layer (`deep.json`) and the recorded real explanation |
| `config.py` | `OPENAI_API_KEY` and `DEMO_MODE` from the environment |

Every AI step has a fallback: with `DEMO_MODE=true`, without a key, or when OpenAI fails, the endpoint answers from recorded real responses (`spikes/openai/recorded/`, `fixtures/deep/explain_recorded.json`) or from curated text, always with `demo_data: true`.

## Scoring (IDEA.md §5)

For each observed term *t* and disease *D*:

- **Hierarchy-aware match.** An exact annotation wins; otherwise the highest known frequency among annotations that are ancestors or descendants of *t* (HPO `is_a`).
- **Not annotated is not absent.** With no match, or a match of unknown frequency, *P(t|D)* is the background frequency, so LR = 1.
- **LR = P(t|D) / P(t|¬D)** when present, and **(1 − P(t|D)) / (1 − P(t|¬D))** when negated. The background is the mean matched frequency over all diseases.
- Log-LRs are summed with a uniform prior and normalised over all 12,867 diseases into a **% match**. The **range** is the 5th–95th percentile over 64 seeded draws inside each HPO frequency band.
- **Next question:** the unasked phenotype annotated in either of the top two candidates that maximises binary information gain.

The same semantics produce the UI sample responses (`app/fixtures/api/generate.py`), so live answers and samples agree; for the demo case, late-onset Pompe ranks first at 3.76%.

## Data (`data/`)

- `fetch.sh` downloads HPO v2026-09-01 into `data/raw/` (not committed).
- `build.py` keeps phenotype annotations (aspect P, not NOT, under HP:0000118). It assigns each disease to the HPO organ system with the most annotations (a galaxy) and to its dominant subsystem (a cluster), places stars on a sunflower spiral, and writes deterministic JSON. `--check` rebuilds in memory and compares bytes.
- `curate/` holds the deep layer: 11 diseases (late-onset Pompe, dystroglycanopathies, LGMD differential), 13 cited edges, 3 patient groups and 8 assets. Study titles and statuses come from ClinicalTrials.gov API v2, and funded projects from NIH RePORTER.

## Frontend (`web/`)

React + Vite + TypeScript + Tailwind v4 + Motion. `App.tsx` renders the constellation full-screen (slot `stage`) and lays out each feature by its exported `slot` (`left`, `right`, `bottom`, `overlay`), so features never edit a shared file. State lives in one zustand store (`lib/store.ts`). `lib/api.ts` falls back to the contract sample when an endpoint is down and shows the "Sample case" badge. The visual system is in `web/DESIGN.md`; `?ui=kit` shows the component kit.
